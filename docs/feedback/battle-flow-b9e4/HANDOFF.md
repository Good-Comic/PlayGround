本報告依使用者 2026-11-05 最新指示，使用臺灣正體中文；程式識別符、原始日誌與四語遊戲介面保留原文。共用文件的雙語預設未被修改，此回報依最新使用者語言指示覆寫。

## 玩家問題與實際改善

使用者指出戰鬥太被動、難以控制。本輪將既有戰鬥能力直接接入持續可見的作戰快捷列，而非調高傷害、改敵軍數量或重寫已完成系統：

- **F2／全軍**：選取可戰鬥部隊；排除村民、英雄、非戰鬥單位、敵軍與死亡單位。不改村民任務。從英雄直控切回時，沿用原生解除直控流程。
- **推進**：選軍並進入正式攻擊前進落點模式；點戰場下令，沿用既有路徑、索敵、視野與碰撞規則。
- **護衛**：選軍後點友軍或建築，沿用正式護衛限制與錯誤回饋，不新增任意地點護衛規則。
- **英雄／Tab**：原生英雄直控；WASD 帶位，F2 切回軍隊。英雄接管會清除尚未落點的軍隊指令。
- **Q 標記**：顯示冷卻與有效目標狀態；未有可見且在正式範圍內的目標時停用。
- **E 神盾**：顯示冷卻及目前正式範圍內可涵蓋的友軍人數；沿用原生效果。
- 技能懸停／聚焦沿用原生範圍預覽；Esc 取消落點即時更新提示。暫停、選卡、結算、對話框與施工時有同步輸入防護。

新增介面只呼叫既有公開命令。`js/game.js`、`js/renderer.js`、`js/targeting.js`、`js/data.js` 相對基準沒有變更，傷害、攻速、費用、波次、卡牌效果、抽卡與模擬 RNG 均未改。

## 原失敗與修正

1. 初測暫停隱藏檢查 FAIL：文字更新節流也延後隱藏。已把可見性判斷移出節流，並等待瀏覽器繪製後驗證；命令入口本來另有同步狀態防護，未發現穿透下令。
2. 初測手機畫面雖在視口內，英雄／標記／神盾被小地圖覆蓋。保留舊圖與命中資料，改用 `elementFromPoint` 和小地圖交集驗證。
3. 第一個定位修正後，900×600 的全軍按鈕仍被其他面板遮擋，保留 `hit-tests-medium-failure.json`。最終將快捷列獨立掛在 body，避開受 transform 影響的 HUD 座標系。
4. 初測100單位 P50 從33.4升至49.9ms，未隱瞞。減少重複 DOM 文字／屬性寫入、移除關聯樣式失效，以及不再因未顯示的目標ID改變而重繪。保留初測與兩輪最佳化數據。

最終四語為繁中、簡中、English、日本語；視口1366×900、1280×720、900×600、390×844。六個按鈕均通過實際命中及不與小地圖重疊的檢查，並非只有邊界在畫面內。

每組先暖機1.5秒，再量測約8秒牆鐘時間的 rAF；序列執行，保留原始筆數與 Heap。場景由相同種子受控生成100／200初始總單位，原生 AI、碰撞、戰鬥與 Canvas 繪圖皆啟用，單位會正常死亡，不維持固定數量，也不宣稱全數始終同屏。受控生成可能超過人口上限，屬壓測夾具，不代表正式生產可超額。

初測100單位 P50 退步後，最佳化重測已回到基準33.4ms。200單位 P95 在其他輪次仍有83.4–100ms波動，整體性能保留 INCONCLUSIVE，沒有標記全部性能 PASS。短測不能證明長期穩定、無洩漏或實體 GPU 表現；Heap 變化亦受 GC 影響。

環境：Linux Chromium154.0.8037.57、AMD EPYC9V74、四 CPU 配額、ANGLE Vulkan SwiftShader 軟體繪圖。不是 Windows Chrome／Edge 實體 GPU 測試。既有低 FPS 模擬時間落後、嚴格完整 Save/Load、歷史自然第四／第五波戰敗、自然十波／NG+與真人聽感缺口保持原狀。本輪 scoped 存讀檔 PASS 僅指護衛命令、技能冷卻與介面狀態，並非嚴格全狀態等價。
