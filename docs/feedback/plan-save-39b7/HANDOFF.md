# 戰術計畫續存與安全恢復

`SCHEDULED_RESUME_EXECUTED`。本輪從已釋放的布令成果接續，新增獨立任務，沒有冒用舊Owner或重做既有暫停／分兵功能。依使用者要求，報告採臺灣正體中文，遊戲介面維持四語。

## 實際新增行為

戰術布令畫面新增「儲存計畫」。它沿用原生存檔槽與存檔流程，保存完整遊戲加上尚未下達的計畫；儲存後保持暫停。讀檔會先恢復模擬狀態，再於第一個更新前恢復暫停計畫，等玩家確認才下令或施法。

分隊移動、進攻移動、指定敵軍集火、護衛與英雄技能均經原布令介面重新驗證。版本、種子、cycle、波次與階段必須相符；失效單位、不可見目標、無效座標、重複命令或尚未就緒的技能安全略過並顯示數量。不同存檔的計畫不會跨局回放。

沒有未下達計畫的舊存檔仍沿用正常繼續流程；原生已下達的指令仍照原遊戲保存。按取消後不帶出舊計畫，重複恢復不重複執行。儲存空間不足時保留當前畫面中的計畫與既有存檔，讓玩家重試，不假裝儲存成功。

存檔只增加可選`tacticalPlan`欄位，未改舊存檔版本，也未改傷害、費用、技能冷卻、抽卡、RNG或戰鬥AI。未保存編輯歷史、視窗焦點與鏡頭操作歷史；讀檔後可重新檢視、編輯、取消或執行計畫。

## 原生遊玩驗證

中國文明NORMAL、種子`PLAN-SAVE-PLAY`，由原生開局透過滑鼠編排步兵、騎兵與神盾。實際儲存、重新載入頁面、點繼續後，三項計畫、模擬時間、RNG、資源與未使用的冷卻完全保留；再等1.2秒仍不自動執行。明確確認後才執行原生命令並進入神盾冷卻。

接著改存普通遊戲，讀檔沒有帶入已執行計畫，也不強迫開啟規劃。原生提前迎戰後繼續作戰，約第81.45模擬秒清除16名敵軍、城心3000HP，正常進入第一波三選一。沒有注入單位、資源、時間、敵軍生命或完成條件；不冒充自然十波或預設倒數戰役。

另一場原生開局`PLAN-TARGET-SAVE`等到實際可見敵軍進入標記範圍，才暫停排定集火與標記並儲存。重載後保持暫停與同一指定目標，等選單轉場結束仍不偷走模擬時間。確認後原生彈道的扣甲前輸入7.7，實際量到1.7HP損失，護盾損失0；這次分開記錄輸入與真正扣血。

## 失敗分類與RNG

100單位續存初測與一次交戰重拍，因直接比較帶號與無號RNG整數而FAIL：`-2111126397`與`2183840899`具有相同32位元。既有`mulberry32.restore`會轉為無號表示；本輪沒有修改該實作。

保留原始失敗與診斷檔，之後比較32位元狀態及兩個獨立RNG副本的後續64個輸出，均一致；不從即時遊戲RNG抽樣。原始數字或嚴格整份快照仍有表示差異，不宣稱歷史嚴格完整Save/Load FAIL已修復，也沒有刪除測試。

儲存空間不足是受控失敗案例：故意使既有localStorage.setItem拋出QuotaExceededError，再恢復原函式；測試確認舊槽內容未變、計畫仍在、遊戲仍暫停，重試成功。正式正常流程沒有覆寫存取函式。

Chrome154.0.8037.57、Linux、AMD EPYC9V74、四CPU配額、SwiftShader環境。每組10次同步儲存及原生continueRun，含第一筆；受控生成100／200初始總單位，保持暫停，只量這些操作的CPU時間，沒有把暫停數據當成戰鬥FPS。恢復後時間與RNG位元狀態固定，獨立64次輸出亦一致。

JS heap起／末約9.76／15.35MiB與8.94／19.72MiB，未強制GC，不宣稱無洩漏或長時間性能通過。新增序列化只發生在存檔與讀檔，不增加戰鬥每幀的計畫序列化。戰鬥FPS未無差別重跑，前輪的軟體繪圖短測仍僅有限證據，低FPS模擬時鐘問題不變。
