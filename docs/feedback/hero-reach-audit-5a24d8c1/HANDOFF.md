# 英雄直控：保留手動目標可越過近戰距離

## 本輪結論：重現成功，未修正

本輪只有合法獨立診斷，沒有修改任何正式遊戲程式。發現比原先1.4距離容差更明確的問題：先右鍵指定可見敵軍，再按Tab直控，英雄原地可對距離4的敵軍造成12點近戰傷害；同兵種一般攻擊的當前距離判定是0.9射程＋0.26目標半徑＝1.16。此差異會讓玩家對接敵距離及控制模式的理解不一致，但未把它宣稱為既有真人失敗或C-36的根因。

## 受控觀察

距離4反例：英雄保持(12,12)未移動，敵HP60→48；敵在自身更新時向英雄接近0.04，最終距離3.96，仍遠超1.16。沒有其他友軍可造成該傷害。

原生滑鼠選英雄、右鍵下令、Tab切控制模式；然後執行真實 `updateUnits(1/60)`。使用受控平坦開闊場景，移除無關實體以隔離影響；正式Crowd碰撞與可見性流程仍啟用，沒有直接呼叫傷害或改敵HP。所有目標在正式視野內，不以讀未發現位置製造反例。不是自然開局、自然存檔續玩或真人趣味評估。

Node方法級另記錄16文明×4距離×2路徑共128筆。Node矩陣明確先設置手動目標；距離4時16文明的直控路徑皆命中，一般路徑皆需接近。這是觀察矩陣，不冒稱128項正式回歸PASS。Chromium只驗證中國文明，不能外推16文明瀏覽器驗收。

## 可追溯原因

- `js/targeting.js` 第3行：為保留人工命令，`manualAttack`且目標可見時直接回傳原目標，不套用本次索敵radius；檔首亦說明距離應由Game判定。
- `js/game.js` `updateHeroDirect`：待命時拿到目標即呼叫 `attackUnit`，沒有再次驗證攻擊距離。
- `attackUnit`不自行檢查距離；一般 `updateAttack`會先檢查距離，故兩模式結果不同。
- 沒有既有目標時，直控使用至少1.5的索敵距離且直接攻擊，因此1.4的差異是另一個同入口表現。是否保留特定直控近身容差需核對原設計；不能用它解釋距離4的人工目標旁路。

正式GDD `docs/gdd/issue-8-snapshot.md` 第63行描述Tab接管、WASD移動及相同Q/E技能，沒有找到允許視野內不限距離近戰的條文。未擅自把缺失條文當成新平衡授權。
