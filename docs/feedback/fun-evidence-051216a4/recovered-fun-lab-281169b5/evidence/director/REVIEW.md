## 優先切片的最小行為與真實程式位置

**玩家可見行為：** 作戰列持續顯示「目前選兵 X／全軍 Y」及其即時命令。至少能區分「移動」「護衛城心／盟友」「人工集火：可見目標名稱」「推進／巡邏」「自動接敵／待命」。護衛中自動打敵人仍以護衛為主，不寫成玩家指定集火；`state='attack'` 僅代表交戰狀態，不能叫「已命中」。多種命令同時存在就顯示混合摘要，不挑選最佳命令。原本全軍數已存在，新增的是選取涵蓋與實際命令的關係。

原始結果 `DIRECT-CHROMIUM-BEFORE.json` 與兩張 `direct-*.png` 均已人工檢視，是真正遊戲場景。公開轉接器的過期 `@` selector、不可見按鈕與 1500ms Playwright timeout 分列為工具／畫面轉換限制；不得轉記遊戲 Bug。

如另要調查 B／C 的命中疑慮：用各自未改自然存檔在直接 Chromium 原生 Continue，先從當下畫面找到仍存活且可見的衝車／旗手；保存右鍵前畫面、實際座標、該點 `pickAt` 讀值與 after 的命令／目標。用原生 `page.mouse.click` 送一次右鍵，禁止內部 ID 下令；再對當下可見目標重新選擇，重複可再現才列缺陷。不同時間的畫面不能靠重點歷史座標還原當時 hitbox；原始 action 的 partial state 也不能偽裝成完整可恢復快照。

## Node、Chromium 與三方重測標準

### Node／定向整合

1. 純讀 helper 以既有真實單位狀態驗證移動、人工集火、護衛、推進／巡邏、自動接敵／待命與混合群；已選與全軍數排除死者、敵軍、工人、英雄及無攻擊單位。顯示人工集火不表示傷害命中。
2. 目標改變、死亡、失去視野、新局、讀檔及切換選取不殘留前一目標；未見目標不得先讀名稱／位置再遮字。沙暴用正式視野判定，不新增視野。
3. 渲染與摘要前後除 UI 資料外的 `snapshot`／RNG／資源／HP／冷卻／命令不變；已有人工新命令仍立即覆蓋援護與舊指令。不能從舊 `orderFailure` 下當下卡死結論。
4. 英雄直控中援護後仍選英雄，摘要必須明確為已選戰士 0／全軍 Y，英雄既有控制、按鍵、命令、鏡頭與選取不變；若選到英雄與軍隊混合群也不能把英雄計入軍令人數。只選工人、建築、敵軍或空選取均不得沿用舊軍隊目標。
5. 沿用相關既有測試：`battle-actions`、`core-defense`、`tactical-orders`、`tactical-partial-feedback`、`visibility`、`rally-objective`；若改 Renderer，再加其可見性／繪製層測試。只跑受影響的檢查，不為此重跑無關長測。

### 直接正式 Chromium

使用實際構建與來源 SHA。先以相同原生 Start／F2／右鍵空地／援護重做兩個已重現情境，要求 1.3 秒、3 秒後摘要仍正確，並可區分移動與護衛。另在清楚標記的定向戰鬥場景測原生右鍵可見敵人後，摘要的目標名稱與 immediate after 一致、可見標示對到同一實體；換成移動後不再顯示集火。需要 fixture 才能穩定測試的敵人／Fog／沙暴案例須標 `CONTROLLED_FIXTURE`，不冒稱自然通關。

角色操作仍只用正常 UI。對未見或已死目標不留標示；Pause／卡牌／對話框／結算不誤發命令；英雄直控保持鏡頭、選取及持續按鍵原語意。1440×900 與至少一個較小視窗、四語字串驗收不遮按鈕、不出 raw key。保留左三選一＋右完整 32 卡樹永久同屏，不因這次改動改成開關。

**硬驗收：** 摘要與實際可見命令相符、人工目標零錯標、Fog／沙暴零情報外洩、後續人工命令優先無回歸。角色報告至少一次能由 UI 正確說出目前命令與目標／護衛對象；若有意圖落差，記錄何時發現、是否修正及所需意圖，沒有自然出現就標未評估，不製造故意誤點。沒使用到某模式不能算那模式通過。

**比較與宣稱：** A 對自己的護衛不等於指定集火窗口，B 對自己的移動／攻擊落差，C 對自己的普通兵／旗手辨識窗口。主指標是語意讀回正確、落差能否被注意與修正、額外輸入／面板成本；正式勝敗、城心／部隊損失、波次、時間都如實記錄為次要結果。三方各有改善、無差異、變差均單獨呈現，不合併投票；沒有通關提升也可能證明控制回饋改善，但只有 UI 靜態 PASS 而角色沒有感受到用途，必須將「更好玩」維持未證實。反之，單次通關也不能宣稱統計平衡或長期留存改善。
