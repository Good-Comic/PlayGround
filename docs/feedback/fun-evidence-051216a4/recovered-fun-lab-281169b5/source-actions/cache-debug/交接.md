## 實作與驗證範圍

每次 UI 更新仍先執行 `observer.view()`；有 pending 時仍立即執行 `validateAction()`。事件／來源／世界／波次／選兵實體／英雄直控／軍令／phase／阻擋等變更的取消沒有節流。驗證先排除已失效的上下文，再於必要的攻擊驗證中重新計算正式戰士；查看憑證不為無用途的人數檢查掃描軍隊。實際 capture／activate 仍重新驗證原生條件，不採用呈現快取授權發令。

兩個實際顯示行均無已確認來源時，不呼叫 `selectedAttackers()`，也不為純顯示建立軍隊／選兵 Set。仍有可見來源時，實際人數、混選及可用性持續重新檢查。

顯示快取逐項比較目前 locale、人數、純戰士選取、可用性，以及最近／顯示中最大事件各自的 token、sourceId、name、direction、loss、at。相同時跳過重複的 rowText、按鈕翻譯／tooltip／aria 格式化及 DOM 讀寫；快取保留的事件 token 有界於這兩個顯示行。只有整次 paint 成功後才記錄；DOM 例外立即清除快取並隱藏額外 UI，下次即使狀態相同或回到上次狀態也會重新呈現。沒有新增 Canvas／native pick 查詢或持續目標搜尋。

另修正實作前即存在的**既有空紀錄 paint 例外**：`showPeak(null)` 原本左側使用 optional chaining，但比較的右側仍直接讀取 `view.loss`。初始無紀錄與清空後的 paint 因此會進入 UI catch，並多計一次 `uiFaults`；這是實作缺陷，並非測試夾具問題。本次加入最小 null guard，使空紀錄正常清理兩行並保持 `uiFaults=0`。未放寬失敗計數預期。
