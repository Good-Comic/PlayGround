## 核准的最小行為

在原有逐建築設定內，保留既有狀態、兵種勾選、目標、權重及預留欄位，補上緊湊、唯讀的「已套用生產規則」診斷。先讓玩家直接看見該兵種的實際一筆費用，以及目前缺少的資源；完整計算可放在同列的簡短展開說明，不另加大型面板或頁籤。

每個已生效方案內的兵種，以 `game.unitCost(type)` 取得正式費用，並以 `reserveCost(game)`、該建築已生效 `budget` 及 `canSpend` 判斷。若顯示未列入已生效方案的兵種費用，必須標明僅供費用參考，不得讓表單勾選外觀暗示它已參與自動生產。

有效兵種集合也沿用原生：`p.units` 非空才採指定集合，未設定或空集合時回到該建築合法且可攻擊的兵種，再套用既有合法性與訓練限制。不能只從表單勾選外觀推斷已生效集合，也不能藉這次說明改寫其回退行為。

對費用大於零的各資源，資料關係為：

```text
目前庫存 = game.resources[r]（依原生零值處理）
這筆費用 = game.unitCost(type)[r]
有效最低庫存 = max(reserveCost(game)[r], 已套用的逐建築預留[r])
付款後庫存 = 目前庫存 - 這筆費用
尚缺 = max(0, 有效最低庫存 - 付款後庫存)
```

用詞應明確表達「付款後最低庫存」，而非「支出額度」「已花費預算」或含糊的可用總額。「可支用餘額」若顯示，須明確定義為高於該底線的庫存部分，不得當成未花費的累計預算。費用為零的資源即使低於其保留，也不阻擋這筆訓練，應顯示「本筆不支出／不檢查」，不能產生虛假的缺口。

計算與 `canSpend` 採相同的先減費用再比較順序，並由原生 `canSpend` 決定是否通過。不得為了讓格式好看加 epsilon、四捨五入後改判斷，或把非零小缺口顯示成零。若精度超出顯示位數，以「小於某顯示精度」等誠實方式保留非零資訊；不要把進位後數字稱為精確原始差額。

資源門檻通過時，只能說「資源條件符合；仍待原有自動檢查與其他條件」。既有 `productionStatus` 的手動、佇列、目標、人口等原因仍優先；費用說明可以同時存在，但不能把它們覆蓋成「資源足夠所以應立即生產」。仍沿用原本檢查節奏與建築輪替，不新增倒數承諾、下一兵種預測、最佳配兵或最佳保留建議。

### 已套用設定與草稿

`steward-ui.js:48–60` 目前只有採集比例會預覽草稿；整份設定在按「套用」時才寫入 `game.stewards`。新診斷必須讀已生效的 `game.stewards`，不得暫時替換全域狀態去算預覽，不得在修改欄位時偷偷儲存。

說明區標示「依已套用設定」及本次開啟／更新時的庫存。表單變更後顯示「有未套用變更；以下仍依已生效設定計算」之類提示。對已修改的年齡政策、全域保留、建築預留、啟用／兵種／目標皆成立，避免玩家把新輸入值和舊診斷混看。

「套用」「關閉不套用」「確認既有待辦」及暫停還原語義維持原樣。確認待辦走 `confirmPlan`，可按已生效規則實際支付；它不應順便套用草稿。原有重新呈現後應重新讀實際庫存及生效設定，不沿用付款前的診斷。這一切片不另改既有草稿生命週期。

## 實作後驗收標準

下列屬於有意義的定向驗證，不要求重跑完整自然十波，也不把技術檢查當成玩家理解改善。

1. **原生 Node 資源語義：** 用正式 Game 的費用與效果驗證各種保留組合；`auto`／`ask`／手動、研究中與滿級均須和 `reserveCost/canSpend` 一致。明驗兩個底線取較大值、未使用資源低於保留仍可通過、非零小數邊界，以及有文明／卡片修正時顯示正式費用。既有排隊不可重扣費用。保留「手動付得起、自動仍等待」的合法案例。
2. **原生 Node 狀態與純讀：** 與既有 `production-status`、`military-rotation`、`steward-recovery` 案例相容；手動、佇列、含全軍排隊的目標、兵種／人口限制仍優先。多次查詢前後完整快照、資源、佇列、總管游標／計時與所有 RNG 狀態不變；在相同起始狀態觀察後執行原有一次訓練，結果與未觀察組相同。不得修改嚴格 SaveLoad RNG 的既有 FAIL 判定。
3. **Chromium／DOM 定向：** 建立明標受控案例，逐列核對實際費用、庫存、有效底線與缺口；通過資源條件仍可能被其他門檻擋住。修改表單後診斷仍據生效設定且有未套用提示；關閉不改遊戲，套用後重開才按新值，確認待辦實付後重新讀值，無隱性套用。四語與代表窄／寬視口可讀，原有固定控制列、鍵盤焦點與暫停還原正常。這是未執行的未來驗證，不沿用其他切片的 Chrome PASS。
4. **玩家定向續測：** 實作與技術檢查封存後，再由有自己合法存檔／上下文的玩家自然操作。讓其自行說明一筆訓練費用、哪個已生效底線限制、尚缺什麼，以及資源通過為何不等於立即生產；觀察能否作出自己的設定／等待決定。保留誤解、找不到、看不懂與操作負擔的原始反證。未套用草稿和已生效規則的辨識另判，不以成功排入一次或勝率代替理解證據。本輪未讀取的來源入口玩家證據維持獨立。

目前已證明的是規則與介面確有可填補的精確說明落差，以及不改規則即可實作的範圍。尚未證明這個新說明會改善三角色理解、減輕負擔、提升樂趣或勝率；也尚未證明它能回答 C 的歷史支出問題。
