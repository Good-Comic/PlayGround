## 關鍵：穩定事件身份與啟用期間取消

目前observer.view只回傳loss／at／sourceId等資料，不能只用名稱、格式化數字或秒級時間當事件身份；同名來源、同秒多擊、raw同值與讀檔新實體都可能碰撞。

建議在觀察器內使用私有事件物件身份或不寫入存檔的事件token，將可操作行明確綁定到當次rendered事件、world、wave、core與source物件。可以給UI不透明token及受限action context；不必把原始敵人物件／座標放進DOM，不新增全場日誌。

- pointerdown先確認**正在顯示的行**仍是目前那筆，才捕捉token；不在pointerdown直接發令。
- native click啟用時再驗同token／同source／同world與wave、身份仍可公開及所有模式條件。事件即使更新成同名來源或同一source的新一擊，也取消本次啟用，不能悄悄操作按下後刷新出的另一筆。
- 選取／人數在啟用內改變時，最小版本可明確取消，避免用未顯示的群體執行；混選／英雄／空選必拒絕。取消不清除原orderMode、不改選取／鏡頭／命令，也不做自動重試。
- pointercancel、失焦、行消失、讀檔／換波／結算使armed狀態失效。正常快照restore即使waveIndex與數值相同，也不能沿用舊source或舊token。
- 鍵盤／輔助啟用也須綁定當時顯示token；Space、Enter重複鍵不能重送。保留原生按鈕Tab焦點導航，不為這個入口改成全域Tab強制切英雄。不同啟用方式可用原生button事件完成，不能只支援pointerdown而讓鍵盤無法使用。
- 非預期／過期click只回傳一般「紀錄或來源已變更，未下令」原因；來源已不可確認時不再在失敗訊息重印舊身份／方向。

這項取消規則會增加部分失敗／重讀成本，尤其last更新頻繁；應量實際取消率及玩家理解，不因它是安全取消就直接宣稱可用性改善。peak較穩定也不是預設最優目標，仍由玩家選行。
