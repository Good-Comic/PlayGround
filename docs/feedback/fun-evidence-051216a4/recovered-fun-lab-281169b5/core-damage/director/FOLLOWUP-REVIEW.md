### 已核實的原生鏈

- Game.js:1953 的實際近戰、:2001 的投射物抵達命中、:2065 的zone對建築命中，都經過 applyDamage(:2076)；只有 target指向城心或 state=attack 並不保證這些分支曾造成失血。
- applyDamage先處理事件倍率、護甲、護盾與早退；真正扣除HP在:2123，之後尚有反射、死亡與敗北等原生處理。amount是原始輸入，不是已扣HP。完全護盾吸收或其他早退不能顯示「城心失血」。
- source由近戰單位、projectile.source或zone.source傳入；投射物抵達時source可能已死亡／失去視野。spawnProjectile(:1985起)保存source與目前飛行座標，沒有可直接拿來當可靠發射原點的獨立歷史origin欄位。
- getTownCenter(:594)是存活玩家core。executeAshfall(:2590起)雖有直接扣建築HP，但排除城心6格，城心自身不受該分支傷害；修復、再生與波後回復不是受傷，不能拿HUD前後百分比差替代命中事件。
- 現行hooks只有combatVfx等，沒有已完成的coreDamage觀察介面；不能宣稱只接一個現成事件就已交付。HUD ui.js:603附近已有objectiveHp，可就近附一行小摘要，避免再加擋戰場的大面板。

### 最小行為與資料界線

1. 只針對當時玩家城心的實際HP下降顯示短回饋。例如「城心剛受傷 −X HP」，另列「最近可見來源：衝車／城心東側（受傷時）」；先做最近一筆，必要時以短窗口合併總失血，但不能把總額都歸到某一來源，也不做傷害排行榜或自動最佳目標。
2. 優先用獨立純回讀外掛包住原生applyDamage：先記目標與HP，**原生只呼叫一次且完整跑完**，再由clamp到0的前後HP算實際損失。過量致命傷只算被扣掉的剩餘HP，護盾完全吸收、修復／回復不誤報。也可加入無副作用的觀察hook，但不能移動／改寫原本分支。觀察或UI失敗不得中斷致命傷、反射或敗北原流程。
3. 必須先確認source在受傷當下存活、屬於當前世界且正式可見，才取得名字或方位；顯示時再驗可見性／存活／世界。任一不成立，僅保留自己的城心失血，來源降為「未確認」，立即去掉名字與方位，不保留霧中追蹤座標或讀出隱藏種類／HP。
4. 方位定義為「受傷當下可見攻擊者相對城心所在方位」，是那次已見事件的有限回饋，不是來源目前位置追蹤。投射／zone不可把source現在位置冒充當初發射原點或落點來向；若無可靠資料就省略方向。嚴格受限的第一版也可只對可見近戰顯示方位，其他僅顯失血與可證明的來源，不為湊完整度猜測。
