## 合法性與程式判斷

**APPROVED_SCOPE_READ_ONLY_CORE_DAMAGE_FEEDBACK。** 這是已授權的城心受傷因果回饋，沒有新戰鬥公式、索敵能力、付費控制或敵情來源。

observeCoreDamage包住原生applyDamage：前段只記錄當時玩家存活城心HP與可公開來源；原生函式以同樣this、參數呼叫一次，完整跑完後才讀前後HP差。沒有重算護甲、倍率、護盾、反射、傷害或改HP。原生return照傳，原生例外不捕捉／改寫；只有觀察前後自己的錯誤被隔離。

實損計算是max(0,原HP)−max(0,原生結束後HP)，且必須有限、正值。完全護盾或未真正扣HP不產生事件；致命過量只計剩餘HP，不把輸入10000當成損失10000。Node以裝／未裝觀察的完整snapshot、兩種RNG與原生結果對照，並實際測觀察失敗仍完成致命傷／敗北、原生異常仍原樣拋出。這支持「觀察沒有攔截致命流程」，不是只靠UI字樣猜測。

### 最小行為與計算

1. 原「上次實損」保留，旁邊增加短行「本波已記錄最大單次 −X HP · 來源／事件時間」。這是一次applyDamage造成的clamp HP差，不是同tick總和、DPS、原amount、名義攻擊力、單位累積輸出或最佳敵人。
2. 只對同一個own-core實際事件流取raw loss的max；先比較未四捨五入數值，再格式化。每波最多保留last及peak兩筆，不存完整傷害清單／unit排行榜，不新增全軍掃描或pickAt。
3. 以既有g.waveIndex換界；newRun／restore／換world／換core與離開既有可見作戰階段清理，不創新的戰鬥時窗、HP閾值或計分規則。waveIndex變更但尚無新命中時，最大值應為「尚無已記錄實損」，不能顯示上一波最高。
4. **明示統計覆蓋：** 建議用「本波已記錄最大」而非宣稱完整「本波最大」；說明只含本次載入後實際觀察到的事件。從同波中段Continue時，不猜恢復點以前最大值、不由目前HP反推，不為補齊歷史新增存檔或重播規則。
5. 未知來源的大傷也必須進max，數字來自自己的HP、可公開；來源仍未確認。不能只在可見敵人中取max而把未知大傷藏掉，也不能把last的已知來源套到peak。
6. 同值時保留哪一筆是UI穩定性的例行實作選擇，建議保留較早事件以免閃動；不以source種類、距離、威脅分數作平手排序或改傷害。這不改任何戰鬥數值。

### 可見性與用途界線

last與peak各自保有自己的來源／事件時間／僅近戰受傷時箭頭。來源同樣必須「事件當時＋目前」活著、可見且屬於當前世界；失效即永久去掉那筆身分及箭頭，再見到也不重追蹤。保留數字與事件時間可以，顯示未知來源，不補霧中座標、類型／HP、投射發射原點或即時位置。

兩筆在同一UI更新去身分，不能把peak藏在節流後而多留身份100ms；暫停／讀檔仍是UI暫態。最大單次旁須保留「歷史事件」含義，不標成「目前最大威脅／優先集火」或一鍵自動選敵；衝車大一擊不等於它造成最多累積傷害。

顯示位置沿用已實測battle-actions，不硬擠回窄窗會消失的objective-card。最多短行，四語／視口驗證不遮指令、技能／旗手控制；讓數字與時間可比較，避免常駐大片列表或額外閃光／音效。

### Native Node／Chromium／玩家標準

**Node：** 以真實原生命中製造大→小、小→大、同值、未知大→已知小、來源A／B不同；核對last與peak數值／事件時間分別正確，未知來源仍能成為最大。測波Index變更即清峰、新局／同波restore不帶舊峰、不假造讀檔前最大；完全／部分護盾與致命overkill仍只算實際HP。分別使last或peak來源死亡／失視野／離開world，確認同次view去身分且不可重新獲取；投射／zone無方向。裝／未裝整份snapshot、兩種RNG、HP／護盾／冷卻／命令及致命敗北完全相同，觀察失敗不攔截原生。執行受影響回歸，不為此無限重跑無關長測。

**正式Chromium：** 新來源與完整資源SHA；用原封A／B自然快照Continue觀察有資料的兩行及可自行改令。大→小、未知來源／失視野、波切換／讀檔等若自然未發生，另標CONTROLLED_FIXTURE。四語×現有視口確認兩行都能讀，命令與旗手控制不遮擋，兩筆隱藏身份立即清除，零page error。不以兩行靜態PASS代替自然控制效果，API成本仍不得叫FPS。
