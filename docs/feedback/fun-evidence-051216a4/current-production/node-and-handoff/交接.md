摘要的小正缺口小於 0.01 時顯示 `<0.01`，其他有約取的摘要標 `≈`；展開表格以原始 Number 的可回讀字串顯示，不稱約數為精確原始差額，不加 epsilon 改判斷。完整數字也放於 `data-value` 供正式 QA 比對。

## 根代理 QA 介面

`productionReadback(game, building)` 對本世界的玩家普通生產建築回傳：

`{producerId, producerType, at, agePolicy, usesFallback, status, globalFloor, producerFloor, units:[{type,cost,resources:{food|wood|gold|stone:{stock,cost,globalFloor,producerFloor,floor,after,checked,shortage}},resourceReady,canTrainNow,restriction,populationRoom}]}`。

城心、市場、非玩家／非本世界或無 building 回傳 null。回傳資料是新建副本，沒有 Game 或建築物件參照；修改不影響遊戲。`productionReadbackHTML(view)` 只轉譯上述資料；`productionNumber(value, compact=false)` 的預設保留原始字串，compact 只用於明示約取的摘要。

正式 DOM 操作：

1. 開啟 `#btn-stewards-hud` 或暫停面板的 `#btn-stewards`。
2. 展開 `#steward-dialog details[data-producer="建築ID"]`；首次 toggle 才建立 `[data-production-content]`。
3. 每兵種列為 `details[data-production-unit="militia"]`；summary 顯示費用與當前缺口，展開後各資源列 `tr[data-resource="food"]`，各格 `td[data-column="stock|cost|globalFloor|producerFloor|floor|after|shortage"][data-value]`。
4. 固定 `button[data-production-refresh="建築ID"]` 重新讀取實際庫存與設定，不重建更新按鈕。
5. `#steward-applied-notice[data-draft="true"]` 及各建築 `[data-production-draft]` 表示有未套用草稿；改回原表單值會清除。讀回永遠仍取正式 `game.stewards`。
6. 關閉不套用與 Escape 還原原暫停狀態。確認待辦仍走原 `confirmPlan`，不套用草稿；原重新呈現之後，重新展開即可取得付款後庫存與研究中保留。
