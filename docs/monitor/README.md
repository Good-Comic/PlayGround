# GitHub progress feed and Supervisor contract

Source/tools branch codex/riftwatch-v224-monitor; data branch codex/riftwatch-progress-feed. The data branch atomically stores PROJECT-STATUS.json,RECENT-EVENTS.jsonl,LATEST-RESPONSE.md,BLOCKERS.json. It is not a website or a live Cloud execution stream. GITHUB_PROGRESS_SYNC_READY only after the publication/external-reader verification; LIVE_CODEX_STREAM_VERIFIED is NOT_TESTED.

Run tools/monitor/progress_feed.py --input CURATED_EVENT.json --out OUTSIDE_TREE_DIR. Default only generates files. Explicit --publish --agent/--execution requires confirmed ownership of the dedicated feed ref. Uses a temporary Git index, normal fast-forward-only commit/push, exact remote-head verification. Semantic event ID makes repeat publication a no-op, avoiding self-referential metadata commits. Git history preserves old snapshots after interruption; last200 events in the current JSONL. Failure never deletes the previous remote snapshot. Source commit, build SHA and event publication commit are distinct.

Input fields are allowlisted. QA entries carry actual tested source and evidence commit/path/blob. Raw terminal/chat/account dumps are not accepted as automatic input; common credential/email patterns are rejected, and evidence uses repo-relative docs paths. This is not a complete DLP guarantee: review curated summaries before publication. No login cookies, private Cloud APIs, API-key storage or external message/notification service is used.

Supervisor checks commits,QA,core gameplay,performance,simulation time,GDD,merge conflicts,interruptions/ownership and candidate deployment. Severity is INFO/PROGRESS/WARNING/BLOCKED/ACTION_REQUIRED. Notify only material failures/decisions, not every heartbeat. Every event exposes Git provenance and push confirmation; a hash proves evidence identity, not that self-reported tests were independently audited. Public repo JSON can be read via GitHub Contents API at the exact feed commit, or the feed branch; read the four files at one pinned commit to avoid mixing snapshots. External AI access still depends on its own authorized browsing capability.

## Codex execution-events investigation

Official openai/codex app-server README and TypeScript SDK README were read at the full source commit recorded in evidence/monitor-v224/codex-source.json. App-server has client-owned stdio/WebSocket JSON-RPC requests/notifications, including turn completion; the SDK hosts CLI executions. These public interfaces do not establish permission to attach to this existing managed Codex Cloud task or access its internal logs/account quota. This session exposes environment status, not a documented authorized Cloud task/event/webhook connector. Current Cloud event export support is NOT_CONFIRMED. No private API or session-cookie probing was performed.

Fallback: Agent proactively publishes source-pinned summaries and a prepared final-response snapshot. This is checkpoint-based progress visibility, not real-time completion/rate/account-quota detection. An external scheduler can read the last valid GitHub snapshot if this Agent stops; no automatic agent invocation or paid API call is enabled.

## Workstream retention / Supervisor reference recovery

PROJECT-STATUS workstreams are carried forward from the same pinned parent snapshot as the event log. The 200-row RECENT-EVENTS window is a display limit, not permission to erase quiet tasks or unresolved blockers. An explicit replacement event for a task can clear its current blockers; Git history retains the prior failure. Repeating that task's latest event remains a no-op even after its row leaves the window. This does not provide unlimited historical event deduplication. Missing/malformed parent status fails closed rather than silently rebuilding incomplete state.

The user-attached supervision conversation is reference material, subordinate to actual Git and confirmed authorization. Its contents and Strategy v2.2.6 remain unread because this session exposes no conversation-reader tool. See docs/evidence/monitor-v226/supervisor-reference.json. Do not infer new deployment permission or rules from an unavailable attachment. Continue independent already-authorized work.
